# Correction corpus format

Correction corpora are files in JSON Lines format (`*.jsonl`): one JSON object per line, UTF-8, no blank lines, no comments. Each object is one case: a program as written and the expected reaction of the correction pipeline.

## Directories

| Directory | Cases |
|---|---|
| `lexical/` | character normalization, lexical and naming rules `L01`–`L24` |
| `bash/` | translation of shell habits, rules `B01`–`B40` |
| `powershell/` | translation of PowerShell habits, rules `P01`–`P42` |
| `bind/` | type and value rules `T01`–`T09`, `V01`–`V04` during binding |
| `mutate/` | cases generated by mutation of valid programs (`generated.jsonl`) |
| `adversarial/` | generated cases where the correct reaction is no correction or `E_AMBIGUOUS` (`generated.jsonl`) and hand-written cases of the same kind (`manual.jsonl`) |

The two corpora are defined by the `corpus` member, not by directory. The mistake corpus is the set of cases without `corpus` or with `"corpus": "mistake"`. The adversarial corpus is the set of cases with `"corpus": "adversarial"`; every case in a directory named `adversarial/` carries it.

## Case

| Member | Type | Required | Meaning |
|---|---|---|---|
| `id` | string | yes | unique within all corpora; lower case letters and digits in words joined by `-` (`mutate-typo-command-0001`, `bash-b15-02`) |
| `input` | string | yes | program text as written |
| `variant` | string | yes | `a`, `b` or `c`: the variant the text is read in |
| `context` | object | no | conditions of the case, see below |
| `expect` | object | yes | expected reaction, see below |
| `program_kind` | string | yes | `read` or `effect`: kind of the program the author intended |
| `intent` | string | yes | `unambiguous` or `ambiguous`: whether the intended program can be determined from the text |
| `corpus` | string | no | `mistake` (default) or `adversarial` |
| `source` | string | yes | `manual`, `generated`, `example` or `model` |
| `note` | string | no | one sentence in English |
| `mutation` | object | no | generator data of a mutation case, see below |
| `probe` | object | no | generator data of an adversarial case, see below |

### `context`

| Member | Type | Meaning |
|---|---|---|
| `base` | string | absolute directory for relative paths; absent means no base |
| `os` | string | `linux` (default), `macos` or `windows` |
| `config` | object | overrides of the keys `correction.*` and `syntax.*`, written as dotted keys (`{"correction.require_first_char": false}`) |
| `lets` | array of strings | names introduced by `let` in earlier statements of the same request |
| `fields` | array of strings | fields of the input record of an expression, when they cannot be derived from the catalog |
| `timezone` | string | IANA time zone for relative and local instants; default `UTC` |

### `expect`

Exactly one of the following forms.

| Form | Meaning |
|---|---|
| `{"canonical": "<text>", "rules": ["L01"], "class": "F"}` | the program runs as `<text>`; `rules` lists the rules of the corrections in report order; `class` is the least certain class among them (`C` < `S` < `F` < `P`) |
| `{"unchanged": true}` | the program runs without any correction |
| `{"error": "E_AMBIGUOUS", "candidates": ["<text>", "<text>"]}` | the program does not run; `candidates` are the expected candidates in rank order, at most three |
| `{"error": "E_UNCORRECTABLE", "fix": ["<text>"]}` | the program does not run; `fix` lists the expected ready replacements, at most three |
| `{"error": "E_ONE_EFFECT", "next_steps": ["<text>", "<text>"]}` | the program does not run; `next_steps` lists the separate programs |
| `{"error": "<code>"}` | the program does not run and fails with the given stable error code |

The members `candidates`, `fix` and `next_steps` are optional; when a member is absent, the corresponding member of the error is not compared.

A `canonical` form may carry `"alternatives": ["<text>"]` for a probable correction of a reading program: the other interpretations, at most three, in rank order.

Texts in `canonical`, `candidates`, `fix`, `next_steps` and `alternatives` are canonical text of variant A, as produced by the canonical printer (`nurt fmt --variant a`), whatever the variant of the input.

### Generator data

Generated cases record how they were built. Runners of the correction pipeline ignore these members; the generator tests use them for a component check of each case.

`mutation` describes one mutation of a valid program: `operator` (for example `typo-command`, `unit-size`, `pipe`), `kind` (the correction kind of the mutated element), `from` (the text of the valid program), `to` (the text written instead) and, for parameters and values, `in` (the command, or the command and parameter joined by `.`).

`probe` names the component that must not correct the case: `check` is one of `literal`, `relative`, `name`, `mode`, `size`, `number` or `duration`; the other members give the written text (`written`), the wrong reading the component must reject (`corrected`, `resolved`) or the readings it must offer (`to`, `alternative`), the stage, and the literal place.

### Example

```json
{"id":"lexical-l01-0001","input":"remvoe \"/srv/app/build/old.log\"","variant":"a","expect":{"canonical":"remove \"/srv/app/build/old.log\"","rules":["L01"],"class":"F"},"program_kind":"effect","intent":"unambiguous","source":"example"}
{"id":"adversarial-tie-0001","input":"lest \"/srv\"","variant":"a","expect":{"error":"E_UNKNOWN_COMMAND"},"program_kind":"read","intent":"ambiguous","corpus":"adversarial","source":"manual","note":"The name is one edit from both list and last."}
{"id":"bind-t02-0003","input":"find \"/srv/app\" |> filter size > 10M |> remove","variant":"a","expect":{"error":"E_AMBIGUOUS","candidates":["find \"/srv/app\" |> filter size > 10mib |> remove","find \"/srv/app\" |> filter size > 10mb |> remove"]},"program_kind":"effect","intent":"ambiguous","source":"example"}
```

## Comparison

A case passes when the reaction of the pipeline matches `expect`:

1. `canonical`: the program is accepted; its canonical text and `canonical` are equal byte for byte after both are printed by the canonical printer, so line breaks of the expectation do not matter; the rule identifiers of the reported corrections equal `rules` in order; and the least certain class equals `class`. Corpora run through binding (`bind/` and every corpus once binding is available) also compare `ast_hash` of the bound tree with the hash of the bound tree of `canonical` read without correction.
2. `unchanged`: the program is accepted with an empty list of corrections.
3. `error`: the program fails with the given code; listed `candidates`, `fix` and `next_steps` equal the members of the error in order.

Every case, passing or not, is also checked against the correction invariants: the bytes of path, glob, regular expression and replacement literals; numbers of `assert`, `first`, `last`, `skip`, ranges, `depth`, `limit` and `timeout`; the set of target-selecting stages; the kind of the changing stage; the mode parameters `mode`, `on_conflict`, `type` of `create` and `recursive`; and the base of relative paths. A violation fails the whole corpus run.

## Measures

| Measure | Definition | Target |
|---|---|---|
| FCR | share of cases with `intent: unambiguous` where the program was accepted and its canonical text or bound tree differs from `expect.canonical`, or was accepted where `expect` is an error or `unchanged` with a different meaning; every such case is critical | 0 |
| AMB | share of `E_AMBIGUOUS` among cases with `program_kind: effect` and `intent: unambiguous` | at most 5% |
| FC | share of cases with an incorrect input whose program was accepted and equals `expect.canonical` | at least 40%, reported |
| FV | share of cases with `expect.unchanged` accepted without correction | reported |

A false correction is never offset by other passing cases. AMB is computed over each corpus separately and over both together.

## Files

- Every file is sorted by `id`.
- Generated files are rewritten only by their generator; a test compares the file in the repository with a fresh generation and fails on any difference. The generator tests rewrite their files when the variable `NURT_REGENERATE_CORPUS` is `1`.
- A test checks every `*.jsonl` file under this directory against this format: members, member values, the form of `expect`, rule identifiers, error codes and unique identifiers.
- `note`, `id` and every other member are written in English; they do not refer to issue trackers, decisions or documents outside the repository.

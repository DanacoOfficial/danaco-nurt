## How the list is built

<Stats>
  <Fact id="crates" />
</Stats>

The tables below list every directory of `crates/`. The description of each crate is the `description` field of its `Cargo.toml` (without the product name where the field repeats it); every crate of the workspace has one. The grouping is the build layer assigned to the crate in `tables/crate-graph.toml`. A crate depends only on crates of the same or a lower layer, and the test `workspace_graph.rs` of `nurt-contracts` fails when a manifest breaks that rule. The functional view of the same crates is on the [overview](/architecture/overview/) page.

The workspace crates take the version 0.1.2 and `publish = false` from the workspace manifest. The two vendored crates keep the versions of their upstream sources, 2.0.3 for `jaq-json` and 0.12.1 for `nurt-pdf-extract`.

## Vendored third-party crates

Two crates of the workspace contain the source of a third-party project. Both are licensed MIT, not by the workspace manifest, and both are named in `NOTICE`.

- **`jaq-json`** is a copy of jaq-json 2.0.3 from crates.io (author Michael Färber). Its manifest states that the only change to the upstream source is a limit on the length of a repeated string (`"x" * n`), implemented in `src/limit.rs`. The workspace keeps the copy because the multiplication is implemented in the value type of the crate and cannot be limited from outside. The crate is not marked as unpublished, so `deny.toml` checks its license like that of any other dependency.
- **`nurt-pdf-extract`** contains the source of pdf-extract 0.12.1 by Jeff Muizelaar. `NOTICE` records that it was changed to use lopdf 0.47 instead of lopdf 0.42. Release 0.1.1 took this step so that the build no longer needs the unmaintained `ttf-parser` crate (RUSTSEC-2026-0192). The library name is `pdf_extract`.

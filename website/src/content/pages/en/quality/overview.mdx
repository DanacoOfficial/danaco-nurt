## Checks and results

Every change to Danaco Nurt passes the workflows in `.github/workflows` and the scripts in `tools/ci` and `tools/release`. The workflows format and lint the code, build and test the workspace on Linux, macOS and Windows, measure line coverage, build the documentation, evaluate the dependency policy, check the content of the repository and the commit messages, and run the test suites of the language bindings, the integrations, the packages and the benchmark of tasks. The release workflow verifies the checksums of the archives, signs them and installs the published packages on clean systems.

The Test job builds the workspace with `--all-targets` and runs every test with `cargo nextest` and the documentation tests with `cargo test --doc`. The Clippy job runs `cargo clippy --workspace --all-targets --locked -- -D warnings` on the three operating systems, so a warning is a failure. The Coverage job runs the six critical crates and then the whole workspace under `cargo llvm-cov` with a failing threshold for each. The Dependency policy job runs `cargo deny` for bans, licences, sources and advisories. Every command uses `--locked`, so a build uses the versions recorded in `Cargo.lock`.

## The layers

1. **Unit and integration tests** run with `cargo nextest` or `cargo test`; the layout is described on the [testing](/quality/testing/) page.
2. **Differential tests against git** run each `git.*` scenario with the `git` program and with the Nurt command and compare the resulting repositories; see [conformance](/quality/conformance/).
3. **Conformance of the language bindings** runs recorded cases through the `nurt-conformance` runner against every binding.
4. **Scenarios on a clean system** run the built archives, not the source tree.
5. **Lint, format, coverage and dependency policy** run on every change in the workflows.
6. **Documentation build checks** keep the pages in `docs/commands` equal to the catalog.
7. **The benchmark of tasks** compares Danaco Nurt with bash and PowerShell 7 as the tool of an AI agent; [performance](/quality/performance/) describes the task set.

## The workflows

The workflow `ci.yml` runs on pushes to `main`, pull requests, merge groups and daily at 04:17 UTC. Its jobs are Format, Clippy and Test (Clippy and Test on Linux, macOS and Windows), Coverage, Documentation, Dependency policy and Check for four additional targets. The daily run sets `NURT_PROPTEST_FULL=1`, so that the property tests generate their full number of cases.

The workflow `hygiene.yml` runs three groups of content checks, ShellCheck over every shell script and `actionlint` over the workflow files, and on pull requests it checks the commit messages and the sign-off of each commit. The workflows `bindings-go`, `bindings-node`, `bindings-python`, `bindings-dotnet` and `bindings-java` build and test each binding on Linux, macOS and Windows (and on Linux aarch64 for all but Go) and lint it with the tools of its language: `gofmt`, `go vet` and `staticcheck` for Go, `mypy` and `ruff` for Python. The workflow `bench-oracles.yml` validates the tasks of the benchmark and runs the reference solutions in bash on Linux and in PowerShell on Windows.

The workflow `packaging.yml` runs the packaging tests, ShellCheck over the installers, the build of the Debian and RPM packages, `lintian` on the Debian packages and the installation of the packages in clean containers. The workflows `integrations-*` cover the container images, the development container feature, the examples, the setup action and the extension for VS Code. The workflow `release.yml` publishes the packages after `sha256sum --check --strict checksums.txt` and `tools/ci/check-dependencies.sh` succeed. Actions used by the workflows are pinned to commit hashes, and the workflows run with read access to the repository contents.

## Reporting a vulnerability

Suspected vulnerabilities are reported by e-mail to `support@danaco-group.pl` with a subject that starts with `[security] nurt`, not in a public issue, pull request or discussion. Reports may be written in English or Polish. The policy is the file [SECURITY.md](https://github.com/DanacoOfficial/danaco-nurt/blob/release-0.1.2/SECURITY.md); the documentation page is [Security](/docs/guide/security/).

A report names the affected version, the system, the issue and its impact, and steps to reproduce. The policy sets these target times:

| Step | Target time |
|---|---|
| Acknowledgement of the report | within 3 business days |
| Initial assessment and severity rating | within 10 business days |
| Fix for a critical vulnerability | within 7 days of confirmation |
| Coordinated public disclosure | within 90 days of the report, or earlier when a fix is released |

Fixed vulnerabilities are described in a security advisory of the repository and in the changelog; a CVE identifier is requested where appropriate, and reporters are credited unless they ask otherwise.

The scope covers the `nurt` executable and `libnurt`, the Model Context Protocol server and the language server, the journal including recovery and undo, the release artifacts and installers, and the continuous integration configuration. Out of scope: vulnerabilities in third-party programs that a Nurt program starts on request, issues that need an attacker who already controls the user account or its configuration files, and denial of service through programs that intentionally consume resources beyond configured limits.

## Supported versions

Version 0.1.0 is the first release; the current release is 0.1.2. Until the first stable release, security fixes are applied to the `main` branch and published in a new release. The support period of stable and long-term support releases will be stated in `SECURITY.md` when they are published.

## Properties of the shell

The documentation lists the properties that limit the effect of a program ([Security](/docs/guide/security/)):

- **Check before effect.** Names, parameters and types are validated against the command catalog before any effect takes place.
- **No shell.** Programs do not pass through a shell; a path is one value and is not split or expanded.
- **One effect per program.** A program with more than one changing or running command is rejected with `E_ONE_EFFECT`.
- **Report.** Each run reports its targets, unusual effects and irreversible effects.
- **Secrets.** Parameters marked `secret` in the catalog are masked in the journal, the report and printed trees. The value of `accounts.password` goes to standard input.
- **Project files.** A project file cannot grant itself trust: the keys that widen trust are ignored in `.nurt.toml`.

## Privilege

The console does not raise privileges by itself. A call asks for the rights of the administrator with the parameter `privilege` (`account`, `elevated`, `auto`) and for another account with `as_user`. Nurt applies no policy of its own: the embedding engine decides, and `privilege.allowed = false` refuses `elevated` and `auto` with `E_PRIVILEGE` and the reason `disabled_by_configuration`. A project file cannot set `privilege.*`.

| Backend | How it works |
|---|---|
| `self` | the process already is the administrator |
| `sudo`, `doas`, `run0` | `nurt elevated-exec` runs with the rights of the administrator and reads one request on standard input; no shell text is built and no password is asked |
| `broker` | the privileged service `nurt-elevation`; reported as `not_installed` until it is released |

Access control is that of the operating system: an account that may run `nurt` through `sudo`, `doas` or `run0` is administrator-equivalent. The elevated process refuses to run unless its identity is the administrator or the account named by `as_user`, and writes its journal entry with the rights of the account that asked. Files changed by a program started with `run` and `privilege: elevated` are not preserved and the entry is irreversible.

The final report of the release session of 0.1.1 (27 November 2026) lists an open point that it assigned to 0.1.2: in the descriptor mode of the account journal, calls that read, move and remove check the chain of directories and then act by path, which leaves a window for replacing a directory with a link (creation of files is not affected). The changelog of 0.1.2 lists no fix, and the account journal files of `nurt-fs` are unchanged between `v0.1.1` and 0.1.2, so the point is treated as open.

## Policy of integrators

The console runs the programs it receives; it does not decide which programs an agent may run. The host enforces its policy before `run`, on data computed without any effect: `nurt check` and `run` with `preview: true` ([policy of integrators](/docs/integrators/policy/)). The document `nurt-check/1` returns the strongest effect, the weakest reversibility, the paths named by the program, the network targets, the programs to run and the command groups. Decisions are made on the corrected and bound program, never on the program text.

## Advisories fixed in 0.1.1

The changelog (section Security, 0.1.1, 27 November 2026) lists changes of the dependency graph. They are advisories in third-party crates, not vulnerabilities reported in the code of Nurt. The changelog of 0.1.2 has no Security section; `deny.toml` is unchanged since `v0.1.1`, and `Cargo.lock` differs from `v0.1.1` only in the version numbers of the workspace crates, so the dependency graph of 0.1.2 is that of 0.1.1. No `cargo audit` or `cargo deny` run of 0.1.2 is recorded.

| Change | Advisory |
|---|---|
| `gix` updated to the 0.91 generation, dropping `heapless` 0.8 (nine advisories about unsound code) | RUSTSEC-2026-0574 to RUSTSEC-2026-0582 |
| unused `netstat2` removed; AVIF encoder of `image` (`ravif`, `rav1e`) removed, which removes `paste` | RUSTSEC-2024-0436 |
| OpenPGP signing and checking moved to GnuPG, which removes `rsa` 0.9 and `crypto-bigint` 0.5 | RUSTSEC-2023-0071, RUSTSEC-2026-0387 |
| `pdf-extract` text extraction taken into the workspace on `lopdf` 0.47, which drops `ttf-parser` | RUSTSEC-2026-0192 |
| `chrono` feature disabled where possible; it stays through `macos-unifiedlogs` and `russh-util` | RUSTSEC-2026-0543, ignored in `deny.toml` with a stated reason |

## What is not claimed

<Callout type="warning" title="No audit is claimed">
  No source in the repository records a formal external security audit, a penetration test or a certification. The changelog records a code review of 0.1.0 that corrected defects in every crate. The checks that exist are in [supply chain and releases](/quality/supply-chain/) and [testing](/quality/testing/). Version 0.1 is not stable.
</Callout>

The Authenticode certificate of `nurt.exe` is issued by Danaco Holding Group Sp. z o.o. itself, so Windows reports the publisher as unverified; see [supply chain and releases](/quality/supply-chain/).

## Dependency policy

The policy is the file `deny.toml`, checked by `cargo deny --locked check`. All dependencies are declared in `[workspace.dependencies]` of the root `Cargo.toml`, come from crates.io only, and are justified in the pull request that adds them ([licensing conventions](/docs/conventions/licensing/)).

| Section | Rule in `deny.toml` |
|---|---|
| `graph` | evaluated for eight targets: Linux, macOS and Windows on x86-64 and aarch64 (Linux in glibc and musl), with all features |
| `advisories` | yanked crates are denied; one advisory is listed, RUSTSEC-2026-0543 (`chrono`, unmaintained, no reported vulnerability), with the reason written in the file |
| `licenses` | allow list of 13 permissive licences (among them `Apache-2.0`, `MIT`, `BSD-3-Clause`, `ISC`, `Zlib`, `Unicode-3.0`), confidence threshold 0.93, five exceptions for single crates |
| `bans` | wildcard version requirements denied; several versions of one crate warn; named crates denied, each with a reason |
| `sources` | unknown registries and unknown git sources denied; only the crates.io index is allowed |

Banned crates include `openssl` and `openssl-sys` (TLS uses rustls), `git2` and `libgit2-sys` (Git support is `gix`), `curl-sys`, `serde_yaml` (unmaintained), `sequoia-openpgp` (LGPL; OpenPGP signatures are made by GnuPG started as a program) and `unrar` (its licence forbids creating a RAR compressor). The workspace code is licensed under Apache-2.0; the crate `nurt-pdf-extract` is a copy of `pdf-extract` 0.12.1 under MIT.

In the workflow [`ci.yml`](https://github.com/DanacoOfficial/danaco-nurt/blob/release-0.1.2/.github/workflows/ci.yml) the job `deny` runs `bans licenses sources` and `advisories` as separate steps, and the workflow has a daily scheduled run (04:17 UTC) for new security advisories and toolchain regressions. `cargo audit` ended with exit code 0 and `cargo deny` 0.20.2 ended without errors (version 0.1.1, 27 November 2026).

## Lock files and fuzz targets

`Cargo.lock` is committed and every CI command uses `--locked`. The fuzz targets have their own manifests, and the lock files of `nurt-syntax` and `nurt-correct` are committed:

| Crate | Fuzz targets |
|---|---|
| `nurt-syntax` | `parse`, `decode_json`, `decode_cbor` |
| `nurt-correct` | `correct` |
| `nurt-syslog` | `journal_file`, `journal_object` |

The targets of `nurt-syntax` cover the parser of program text and the JSON and CBOR decoders of the syntax tree, and the target of `nurt-correct` covers the correction stage.

## How a release is built

The script `tools/release/build-release.sh <version> <output-dir> [--sign <gnupg-home> <key-id>]` builds and packs the archives, writes `checksums.txt` and, with `--sign`, a detached armoured signature `checksums.txt.asc`, which it verifies with `gpg --verify`. A key is never read from a default location: `--sign` needs an explicit GnuPG home. `packaging/release/pack.py` assembles each archive: the entries are sorted, owned by root and carry the time given by `SOURCE_DATE_EPOCH` (the commit time of `HEAD` when unset), so that the same inputs give the same archive.

The script builds the executable and the C library for Linux on x86-64 and aarch64 in glibc and musl forms, and for Windows on x86-64 and aarch64 with MSVC. Version 0.1.0 shipped Linux (glibc, x86-64) and Windows (MSVC, x86-64) archives, and version 0.1.1 added the static musl archive; the release session of 0.1.1 built 12 archives of six targets, a program archive and a library archive for each. The variable `NURT_MSVC_CLANG` names the clang of the MSVC wrappers of the Windows build. The Linux musl and aarch64 builds use `zig cc` through the wrappers in `packaging/release`.

The workflow `release.yml` ("Publish packages", started with a version) builds the musl archive from the tag, downloads the archives of the release and runs `sha256sum --check --strict checksums.txt`. It checks with `tools/ci/check-dependencies.sh` that Linux binaries name no shared library outside `libc.so.6`, `libm.so.6`, `libgcc_s.so.1`, the dynamic loaders and `linux-vdso.so.1`. It then signs the checksums and the apt repository, builds the Debian packages, renders the manifests, updates the Homebrew tap and the Scoop bucket, and installs the published packages on clean systems. Actions used by the workflows are pinned to commit hashes.

## Verifying a release

Every release carries `checksums.txt` and its signature `checksums.txt.asc`. The key, as named in `SECURITY.md`:

```text
Danaco Nurt (Danaco Holding Group Sp. z o.o.) <support@danaco-group.pl>
5BEC C5F4 067A 8392 8961  8DB7 65E3 E606 1204 E0FC
```

```sh
gpg --import danaco-nurt.asc
gpg --verify checksums.txt.asc checksums.txt
sha256sum --check checksums.txt
```

The public key is `packaging/release/danaco-nurt.asc`. The tag of every release is signed with the same key (`git tag -v`). The 12 archives of version 0.1.1 passed `sha256sum -c` and the signature of `checksums.txt` is valid (version 0.1.1, 27 November 2026). `nurt.exe` carries an Authenticode signature; its certificate is `packaging/release/danaco-nurt-codesign.pem`, with the subject `C=PL, O=Danaco Holding Group Sp. z o.o., CN=Danaco Nurt`.

## Signed commits and sign-off

Every commit of the `main` branch is signed with a separate OpenPGP key used for commits only, certified by the release key (`packaging/release/danaco-nurt-commit-signing.asc`, fingerprint `62F8 7C0F 4898 35EF 1C94  EF96 0664 7EE7 17FB BC62`). The history is verified with `git log --show-signature` or `git verify-commit`. Contributions are accepted under the Developer Certificate of Origin 1.1; every commit has a `Signed-off-by` trailer matching its author, and `tools/ci/check-commits.sh` checks it in the `commits` job of the hygiene workflow on every pull request ([engineering standards](/quality/engineering-standards/)). The script skips the commits listed in `tools/ci/commits-allow.txt`, which were published before the checks applied to them ([commit conventions](/docs/conventions/commits/)). The transfer into the public repository recreated 145 commits with signatures and corrected subjects (version 0.1.1, 27 November 2026).

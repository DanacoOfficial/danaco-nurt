## What the console does with a habit

A line that starts with a bash command is read with the rules of the POSIX shell, and a line that starts with a cmdlet of the form `Verb-Noun` is read as PowerShell. The console translates the line to a Nurt program and shows both `corrected` and `ran`, the program that was executed ([bash migration](/docs/guides/bash-migration/), [PowerShell migration](/docs/guides/powershell-migration/)).

A translation that rests on an assumption and touches the target of a change is not applied. The answer is `E_AMBIGUOUS` with ready programs, and a call with `accept` runs the candidate you choose. The cheat sheets state the result of every habit: corrected automatically, rejected with an error that carries the fix, or rejected with an error that carries no program.

## What is the same

- Familiar command names are kept as synonyms: `cat`, `ps` and `which` are read by their bash meaning when the arguments are those of bash.
- A pipe `A | B` becomes `A |> B` when both sides translate, and `Where-Object`, `Sort-Object` and `Select-Object -First` map to `filter`, `sort` and `first`.
- Conditions, loops, functions and script parameters of bash are translated since 0.1.1: `if`, `elif`, `else`, `case` and the tests `[ ]`, `[[ ]]` and `test` become `when`; `for`, `while` and `until` become `each`, `while` and `repeat until`; functions become `define`; `$1`, `$2`, `$@`, `shift` and `getopts` become a `params` block.
- `sudo`, `doas` and `run0` are translated into the call parameter `privilege: elevated`, and `sudo -u NAME` into `as_user`.
- An existing script keeps running: `run ["bash", "script.sh"] cwd: "/srv/app"` starts it unchanged, and `nurt migrate` translates a script to a Nurt program and reports what it could not translate.
- `-WhatIf` of PowerShell becomes the call parameter `preview: true`.

## What differs

- **No current directory.** There is no `cd`. A path is absolute and quoted, with `/` as the separator on every system, and a relative path needs the call parameter `base`. `cd D && CMD` is translated only for an absolute path in the same line, as the `cwd` of `run`.
- **Records instead of text.** A stage returns records with named fields, so `ps aux` becomes `processes` and the later stages filter on fields.
- **One changing effect per pipeline.** A pipeline with two changing stages joined by `&&` or `;` is not executed as written: the error `E_ONE_EFFECT` offers the same changes inside `steps { … }` as the first candidate. A `steps` block is one journal entry, all or nothing.
- **No `eval`, no interactive shell.** `Invoke-Expression` is rejected because the language has no `eval`, and `sudo -i` and `su` end with `E_AMBIGUOUS`, because an elevated session is not a command. The console never asks for a password.
- **Recursion is the default.** `rm -rf` and `cp -r` need no counterpart of `-r`, and a missing path is skipped.
- **Undo.** A change to files is recorded in the journal and can be reviewed and reverted with `history` and `undo`; effects outside the file system are recorded as irreversible, unless the command has an inverse operation.

## Paired commands

The pairs are rows of the cheat sheets. The paths are those of the host named in each sheet.

| Habit | Nurt | Result in the cheat sheet |
|---|---|---|
| `rm -rf /home/user/app/build` | `remove "/home/user/app/build"` | corrected automatically |
| `mkdir -p /home/user/app/out` | `create "/home/user/app/out" type: directory` | corrected automatically |
| `tail -n 20 /home/user/app/a.log` | `read "/home/user/app/a.log" last: 20` | corrected automatically |
| `sed -n '10,20p' /home/user/app/a.go` | `read "/home/user/app/a.go" lines: 10..20` | corrected automatically |
| `ps aux` | `processes` | corrected automatically |
| `systemctl restart nginx` | `services name: "nginx" \|> restart` | corrected automatically |
| `sudo systemctl restart nginx` | `services name: "nginx" \|> restart privilege: elevated` | corrected automatically |
| `git -C /home/user/app status` | `git.status "/home/user/app"` | corrected automatically |
| `npm run build &` | `run ["npm", "run", "build"] cwd: "/home/user/app" background: true` | error without fix: `&` is not part of the language |
| `Get-ChildItem C:\Users\user\app -Recurse -Filter *.go` | `find "C:/Users/user/app" glob: "**/*.go" type: any hidden: false` | corrected automatically |
| `Get-Content C:\Users\user\a.log -Tail 20` | `read "C:/Users/user/a.log" last: 20` | corrected automatically |
| `Get-Process \| Sort-Object WorkingSet -Descending` | `processes \|> sort memory order: desc` | corrected automatically |
| `Restart-Service nginx` | `services name: "nginx" \|> restart` | corrected automatically |
| `Set-Location C:\Users\user\app` | `run ["make"] cwd: "C:/Users/user/app"` | error without fix: there is no current directory |
| `Invoke-Expression $command` | `run ["pwsh", "-Command", "Get-Date"] cwd: "C:/Users/user"` | error without fix: the language has no eval |

A habit that has a safe form is written once and then repeated in the Nurt form:

```nurt
find "/srv/app" glob: "**/*.tmp" |> remove
```

The console lists the targets it computed before the removal, and the journal keeps the removed files, so an `undo` restores them.

A list of changing commands becomes one block with one journal entry (bash migration guide):

```text
mkdir -p /srv/out && cp -a /srv/in/data.csv /srv/out/
```

```nurt
steps {
    create "/srv/out" type: directory
    copy "/srv/in/data.csv" into: "/srv/out"
}
```

<Callout type="warning" title="Limits of the translation">
  Only forms that depend on the shell itself have no translation in bash: `eval`, subshells and groups, the arithmetic `for`, `select`, interactive input and here-documents other than `cat > file`. A loop body that uses `$x` inside a longer text, a pipe into `while read` and any `A || B` other than `test … || CMD` and `CMD || true` are also not translated. `ForEach-Object` has no counterpart in PowerShell except a block that reads one property, which becomes `select`; the constructs of a PowerShell script are written in Nurt by hand. A flag without a counterpart is an error that lists the parameters of the command. A line is read as a bash command only when it shows notation that only the shell has, such as a flag, an operator or `$NAME`; a first word that Nurt does not know needs none of these.
</Callout>

## The platform sides

On Linux and macOS, `attributes`, `services` and `package.install` take the place of `chmod`, `systemctl` and the package managers, and the case rules of file names differ between systems ([Unix guide](/docs/guides/unix/)). Since 0.1.1 the administration programs `useradd`, `usermod`, `userdel`, `groupadd`, `mount`, `sysctl -w`, `modprobe`, `ufw`, `firewall-cmd`, `nft`, `iptables`, `ip route`, `timedatectl`, `shutdown`, `parted` and `mkfs.*` are translated into the native commands of the group `administration`. On Windows, the registry is addressed as a path with the prefix `registry:`, `windows.cim` replaces `Get-CimInstance` and `Invoke-CimMethod`, and files in code pages such as 852 or 1250 are read with `encoding` ([Windows guide](/docs/guides/windows/)). The registry provider is available only on Windows.

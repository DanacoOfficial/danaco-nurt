## Version 0.1.2

**Added.** A setup wizard for Windows: the release publishes `nurt-<version>-<target>-setup.exe` for `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`, one file that carries the program archive. The wizard guides through the requirements, the license, the scope (current user or all users) and the integration: `PATH`, shortcuts, a Windows Terminal profile, PowerShell completion and a first `nurt.toml`. Every change is written to the journal `setup-journal.jsonl`; Repair, Update and Undo reverse it, and `/S` installs without a window. The release signs `nurt.exe` and the setup files with Authenticode ([installation](/docs/guide/installation/)).

**Fixed.**

- Search and replace with a regular expression derive the bounds of the line of a match from the match. 20,000 matches on a line of 60,000 bytes are replaced in about 0.1 s instead of 2.5 s.
- `nurt check` accepts a valid program whose argument is a duration, a size, a regular expression, an instant with a zone or a map of literals (`sleep 500ms`, `journal.limits age: 5m`), and a command whose argument is computed before the stage runs.
- Variant C prints a program with a sub-pipeline in the condition of `when` or `while`, in the source of `each` or in the options of a loop, and prints a `bool` parameter written as a bare word as `persistent=true`.
- The record kinds `program_card`, `program_location` and `program_category` declare the fields that the `program.*` commands add to their records, so `select`, `filter`, `sort` and `evaluate` accept them.
- A start of `nurt` completes while another process keeps the lock of a journal entry that is due to expire.
- macOS: the journal is active for the paths of the data volume. The volume reports the mount point that holds its paths, so the directories of the volume serve as journal anchors.
- macOS: `max_memory` applies to every start of a program. The address-space limit (`RLIMIT_AS`) is applied on Linux; on macOS the resident memory is measured.
- macOS: the member list of a group is read without assuming the alignment of `gr_mem`, and suspending, resuming and stopping a program whose process group has ended complete without `EPERM`.
- macOS: the change tracking of `nurt-proc` waits for the delivery of the events of FSEvents before it reads them, and the service accepts a connection whose peer has already closed.
- Documentation: 24 examples are corrected to programs that the language accepts, and 35 examples use absolute paths.

**Changed.**

- The archive `nurt-lib` of the musl targets is about four times smaller: the archive of `x86_64-unknown-linux-musl` shrinks from 235 MB to 63 MB, with the same exported functions.
- Unix: an elevated process that writes the journal of an account names every entry relative to the descriptor of its checked directory (`openat` with `O_NOFOLLOW`, `renameat`, `unlinkat`), so a directory of the journal cannot be swapped for a link between the check and the write.
- Catalog: `package.install`, `package.remove`, `package.upgrade`, `start`, `enable` and `disable` are classified as `reversible_if_preserved`, with a note that states the condition; `undo` has restored them by the inverse operation since 0.1.1.
- `nurt serve --socket <path>` is a reserved option that ends with exit code 3; a host connects with `nurt serve --stdio`.
- Conformance: the binding cases agree with the specification and with `nurt serve`; all 23 cases pass in Python and Node and 22 in Go, and the suite `conformance/tools/test_suite.py` passes.

**Platforms.** The release has archives for Linux (glibc and musl) and Windows (MSVC), each on x86_64 and aarch64, and the setup wizard for Windows. On macOS the program is built from source; the code passes `cargo check` and the tests of the continuous integration on the macOS runner.

## Version 0.1.1

**Added.**

- Named pipes and device nodes with `create` on Linux and macOS; `undo` removes them.
- Administration commands for the firewall, the network, the clock, accounts, groups, mounts, the kernel, power and disks, each with a state report before and after and an inverse for `undo` where the change is reversible ([administration guide](/docs/guides/administration/)).
- Method calls of `windows.cim`.
- Privilege elevation with the parameters `privilege` and `as_user` and the backends `self`, `sudo`, `doas` and `run0`; elevated entries in the journal of the account.
- The command [`next`](/docs/commands/next/) and the field `continuation` for reading the rest of a shortened response.
- Translation of bash conditions, loops, functions and script parameters into the constructs of the language ([migration guide](/docs/guides/bash-migration/)).

**Changed.**

- Control constructs `when`, `each`, `repeat until`, `while`, `steps`, `define` and `params`, and syntax tree version 1.1; documents of version 1.0 are read unchanged.
- `sql` accepts every statement: a statement that changes data journals the database file first.
- The response of `run` is short by default, and `run.spool_max` defaults to `1gib`.
- The journal handles an operation on thousands of small files several times faster. Manifests of operations with at least 256 targets have format version 2; journals written by 0.1.0 are read unchanged.
- On Linux the executable and the library link liblzma statically, and the program runs on a system without `liblzma.so.5`.
- The start banner of an interactive session shows the mark of Danaco Nurt in silver `#DDE1E6` and gold `#C9A15A`.

**Security.** The Git library `gix` moves to the 0.91 generation. Unused dependencies are removed. OpenPGP signatures of commits and tags are made and checked by GnuPG.

**Fixed.** The code review of 0.1.0 corrected defects in every crate, the bindings, the packaging and the documentation. The bindings for Python, Go, Node, Java and .NET read the answers of the engine in the shape it returns. Change detection finds a file rewritten with the same size within the timestamp granularity of the file system and restores it on undo.

## Version 0.1.0

The first release, dated 2026-11-22. Added:

- the Cargo workspace with the crates of the engine, the command line program and the C interface;
- the command catalog and the specification documents;
- the language with three syntax variants, correction of programs, help, and migration of Bash and PowerShell programs;
- the engine with structured reports of effects in text, JSON and Markdown;
- the undo journal with recovery, retention limits and history queries;
- the command line program with the subcommands `exec`, `check`, `script`, `repl`, `serve`, `journal`, `mcp`, `lsp`, `migrate`, `service` and `ext`;
- the Model Context Protocol server, the language server, the C interface (`libnurt`, `nurt.h`) and bindings for several languages;
- packaging for Linux, macOS and Windows, and the OpenPGP signature of `checksums.txt` and of the release tag.

## Archives

The packaging definitions in [packaging/](https://github.com/DanacoOfficial/danaco-nurt/tree/release-0.1.2/packaging) name a program archive `nurt-<version>-<target>` and a library archive `nurt-lib-<version>-<target>`. The archives are `.tar.gz` for Linux and macOS and `.zip` for Windows.

| Target | Form |
|---|---|
| `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` | glibc |
| `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` | static program archive |
| `x86_64-pc-windows-msvc`, `aarch64-pc-windows-msvc` | MSVC |
| `x86_64-apple-darwin`, `aarch64-apple-darwin` | macOS |

The program archive of Linux holds `nurt`, `LICENSE`, `NOTICE`, `README.md`, `CHANGELOG.md`, manual pages, completion scripts and the documentation site. The Windows archive holds `nurt.exe` and the same texts at the top level. The installation page describes the package managers and the scripts: [Installation](/docs/guide/installation/).

## Verifying a download

Every release has `checksums.txt` with the SHA-256 digests of its archives and the detached OpenPGP signature `checksums.txt.asc`. The key is `Danaco Nurt (Danaco Holding Group Sp. z o.o.)`, fingerprint `5BEC C5F4 067A 8392 8961 8DB7 65E3 E606 1204 E0FC`, published as `packaging/release/danaco-nurt.asc`.

```sh
gpg --import danaco-nurt.asc
gpg --verify checksums.txt.asc checksums.txt
sha256sum --check checksums.txt
```

The tag of each release is signed with the same key (`git tag -v`), and `nurt.exe` carries an Authenticode signature. `install.sh` and `install.ps1` check the SHA-256 digest before they install; `install.sh` also checks the signature of `checksums.txt` when it receives a public key with `--public-key`. The full procedure is in [SECURITY.md](https://github.com/DanacoOfficial/danaco-nurt/blob/release-0.1.2/SECURITY.md) and on [supply chain](/quality/supply-chain/).
